## 二、比赛任务拆解（2026 规则，总分 710）

规则要求：机器人自主进场 -> 在 4 个房间（客厅 / 卧室 / 餐厅 / 厨房）巡游 ->
识别出 3 位主人及其行为 -> 做对应交互 -> 捡 3 个垃圾丢进垃圾桶 -> 自主离场。
**每队 8 分钟，可无限次重启，取最好一次成绩。全程只能用中文语音交互。**

| # | 评分项 | 分值 | 我们现在有什么 |
|---|---|---:|---|
| 1 | 自主进场到指定位置 | 10 | 已有导航框架，缺地图 + 航点 |
| 2 | 区分出每个主人（3 x 50） | 150 | 新版：人脸 + 人体 ReID + 语音注册，代码齐，未真机验证 |
| 3 | 判定每个主人行为（3 x 30） | 90 | 新版：YOLO-Pose + Qwen 视觉 + 点云三层融合，**但缺核心文件** |
| 4 | 人机交互操作（3 x 50） | 150 | 代码齐；但新版 ASR 依赖本机未安装的 faster-whisper |
| 5 | 找到地上垃圾（3 x 20） | 60 | 完全没有 |
| 6 | 捡起垃圾（3 x 50） | 150 | 完全没有 |
| 7 | 放入垃圾桶（3 x 30） | 90 | 完全没有 |
| 8 | 正确完成后自主离场 | 10 | 有代码 |
| | **合计** | **710** | |

三种主人行为（**出现顺序随机**）：

1. **躺着/坐着**（床、沙发、椅子）-> 主人用语音说开/关电器 -> 机械手末端移到电控“开/关”标记正上方
2. **摔倒** -> 机械臂末端伸到人体正上方，模拟“扶起”
3. **挥手** -> 走近后语音对话，把主人的求助需求**按原意复述**

### 硬性资格门槛（不满足直接不能参赛）

- **必须有机械臂 + 机械手**（规则里特别强调）
- 身高 140-180 cm，宽 <= 90 cm，重 <= 150 kg
- 自带扬声器，且**处理器必须在机器人本体上**（不能靠外部电脑远程算）
- 明显可见的启动按钮与急停按钮
- 必须有学校 / 队伍标识

### 资格认证材料（报名时就要交，第一部分不交直接取消资格）

| 部分 | 内容 | 硬性要求 |
|---|---|---|
| 第一部分（**必交**） | 队伍介绍 | 宋体小四、1.5 倍行距、**>= 4 页** |
| | 机器人功能展示视频 | **10 MB 以内**，时长 2-3 分钟 |
| | 机器人技术介绍 | 宋体小四、1.5 倍行距、**>= 6 页 PDF** |
| 第二部分 | 近 3 年获奖证明 | 无则交情况说明 |
| 第三部分 | 论文 / 专利证明 | 无则交情况说明 |

整个压缩包 **<= 20 MB**，命名 `XX单位_资格认证材料`，发到 `servicerobothome@163.com`。
**这一项没做，技术再好也没资格上场，请务必尽早安排。**

### 两版仓库怎么选

**结论：以新版为基底做合并，不要整体替换工作区。**

| 模块 | 用哪版 | 原因 |
|---|---|---|
| 人体 ReID / 语音注册主人 | **新版** | 旧版没有，这是真实增益，能解决躺姿、侧身时认不准主人的问题 |

| 语音识别 ASR | **旧版** | 新版删了 SenseVoice 且未装 faster-whisper；旧版已实测可用 |
| 语音采集设备策略 | **新版思路** | PulseAudio 自动找 Xbox 麦并设增益，比硬编码 `Generic_1` 更稳 |

## 四、分阶段路线图

> 原则：**先把一条最稳的“拿分主线”跑通，再加难度**。
> 建议主线：进场 10 + 识别 3 主人 150 + 行为 90 + 交互 150 + 离场 10 = 410 分，
> 这条线仓库已有代码（其中行为 90 分和交互 50 分有依赖缺口，见阶段 4 的 B / C 组）；
> 垃圾 300 分作为第二阶段攻坚。
>
> 新版仓库的人体 ReID + 语音注册能显著提高“识别 3 主人”这 150 分的稳定性，
> 是本次升级里最值得优先落地的能力。

### 阶段 0：ROS 入门（1-2 天，不可跳过）

必须先建立手感，否则后面所有报错都无法定位。

```bash
# 三条终端演示，理解 节点 / 话题 / 坐标
roscore
rosrun turtlesim turtlesim_node
rosrun turtlesim turtle_teleop_key
```

必背的 6 条命令（桌面 `test.txt` 里有更完整版）：

```bash
rosnode list                 # 有哪些节点
rostopic list                # 有哪些话题
rostopic echo /odom          # 看某个话题的数据
rostopic hz /scan            # 看某个话题的频率
rosrun tf tf_echo map odom   # 看两个坐标系的关系
rqt_graph                    # 图形化看节点连接
```

注意 `source` 顺序（`~/.bashrc` 已配好，手动开终端时不要搞反）：

```bash
source /opt/ros/noetic/setup.bash
source ~/catkin_ws/devel/setup.bash   # 必须在上一行之后
```

### 阶段 1：分模块验证（3-5 天）

每个模块单独跑通、单独排错，不要一上来就启动全套。

```bash
# 1) 底盘（会看到 /odom、/imu/data_raw）
roslaunch wpb_home_bringup minimal.launch
rostopic echo /odom

# 2) 激光雷达（会看到 /scan_raw 和 /scan）
roslaunch wpb_home_bringup lidar_base.launch
rostopic hz /scan

# 3) Kinect2（会看到 /kinect2/qhd/... 一堆话题）
roslaunch wpb_home_bringup kinect_base.launch
rostopic hz /kinect2/qhd/image_color_rect

# 4) 机械臂 —— 注意：这一步机械臂会真的动，先清空周围空间！
roslaunch wpb_home_bringup mani_test.launch
```

随时可以用 `~/catkin_ws/competition/robot_selfcheck.sh` 一次性自检全部硬件。

### 阶段 2：建图 + 导航 + 航点（5-7 天，最关键）

这是所有任务的底座。

```bash
# 建图：启动 SLAM，另开终端遥控机器人走遍场地
roslaunch wpb_home_tutorials gmapping.launch

一键启动 WPB Home 机器人教程包中预先配置好的 gmapping 建图功能。它通常会启动 gmapping SLAM 节点、相关传感器/底盘节点、TF 和 RViz 等，让机器人可以通过激光雷达构建二维地图。

# 地图满意后保存（不要覆盖原厂地图）
rosrun map_server map_saver -f ~/catkin_ws/competition/maps/field_map

# 把 map.yaml / map.pgm 放进教程包的地图目录
cp ~/catkin_ws/competition/maps/field_map.* ~/catkin_ws/src/wpb_home/wpb_home_tutorials/maps/

# 用新地图测试导航
roslaunch wpb_home_tutorials nav.launch
# 在 RViz 里点 "2D Nav Goal" 下发目标点
```

接着用 **MapTools 插件**设置航点（配合 `waterplus_map_tools`），本赛项至少需要：

- 4 个房间航点：`living_room`、`kitchen`、`bedroom`、`canteen`
  （房间航点放在**房间中央空旷处**，避免定位误差导致“自己站在障碍物里”而规划失败）
- 起始 / 离场航点：进场门外的 `entrance` 与出口门外的 `exit`
  （**离场门外的区域也要扫进地图**，否则出去那一段会规划失败）
- 航点文件位置：`~/waypoints.xml`（仓库默认读这个路径）

### 阶段 3：语音（基本已完成，1 天收尾）

```bash
# 启动语音合成与播放
roslaunch offline_voice_bridge offline_voice_zh.launch
# 另一终端让机器人说话
rostopic pub -1 /voice/say std_msgs/String "data: '我已经识别到主人。'"
```

已在用的参数：音色 `~/piper/voices/zh_CN-huayan-medium.onnx`，
播放设备 `plughw:CARD=Generic_1,DEV=0`（**默认设备在本机没有声音输出，必须指定这张卡**）。
如果觉得语速不对，加 `tts_length_scale:=1.15` 调慢。

### 阶段 4：部署比赛包 + 主人注册（约 1.5 周）

先跑原厂例子确认相机链路：

```bash

roslaunch wpb_home_tutorials obj_detect.launch     # 桌面物体检测
```

然后按 A -> B -> C -> D 四组顺序部署新版比赛包。**A 组完全不需要联网，
做完就能看到真实的编译报错清单，是性价比最高的起点。**

## 五、已知的坑（提前避开）

1. **Kinect 丢包**：日志里反复出现 `20 packets were lost`。Kinect v2 需要独占 USB 3.0 带宽，
   请插在蓝色 USB3.0 口上、不要和其它大带宽设备共用一个 hub。真机跑 SLAM 前先确认
   `rostopic hz /kinect2/qhd/image_color_rect` 稳定在 30 Hz 附近。
2. **音箱默认设备无声**：本机 ALSA 默认设备指向 HDMI，必须显式用 `plughw:CARD=Generic_1,DEV=0`。
3. **麦克风选择**：card 1 是机身内置麦（近场好），card 2 是 Kinect 麦克风阵列（远场拾音更合适）。
   比赛时人离机器人有距离，建议实测后择优。
4. **不要用 sudo 跑 ROS**：会产生 root 权限的文件，之后 `catkin_make` 报权限错。
5. **同一时刻只能有一个 roscore**：端口 11311 被占用是最常见的“莫名报错”原因。
6. **地图与航点朝向**：取物 / 交互类航点必须让机器人**面朝目标**，否则相机拍不到。
7. **规则明令**：比赛中任何人不得触碰机器人、不得触碰待操作物品、机器人不得触碰场地道具，
   一旦发生就要重启 —— 所以宁可慢，也要把避障留够余量。
8. **新版是“回归版”，别整体覆盖工作区**：上一轮已经把旧包适配成 SenseVoice +
   固定声卡并实测通过，新版是重新导出的原始版，这些适配全部丢失。
   请走“以新版为基底做合并”的路线。
9. **动作识别会静默降级**：缺 `qwen_action_recognition_node.py` 时，
   `init_action_recognizer()` 只打一条 warning 并把 `action_ready` 设成 False，
   任务照常往下跑但行为判定和摔倒 / 挥手分支都不工作。
   每次启动都要在日志里确认出现 `Owner Qwen action recognition ready`。
10. **PulseAudio 独占采集设备**：新版走 PulseAudio，同一时刻只能有一个进程抓麦克风。
    调试时不要同时开 `offline_asr_node` 和 `local_switch_command_test.py`，
    否则麦克风会被抢占、识别全空。采集异常时可跑
    `tools/repair_xbox_nui_audio.sh` 修复路由。
11. **4 GB 显存要算账**：YOLO-World 常驻 GPU，所以新版的 Qwen 视觉模型特意设成
    `action_llm_num_gpu: 0` 走 CPU。**不要随手改成 GPU**，很容易 OOM 把整个感知链路拖垮。
12. **别人仓库里的主人数据一律不能用**：`data/reid_owner_voice/*.npz` 和
    `data/owner/*` 都要换成你自己注册 / 拍摄的。
13. **地图是假的**：仓库自带的 `maps/map.pgm` 只有 1024x1024 且几乎全是空白，
    看着能用其实不是场地地图，务必自己建图。
14. **`catkin_create_pkg` 要先 source ROS**：否则报
    `the following arguments are required: --rosdistro`，
    看着像命令用错，其实是环境变量没加载。
15. **launch 会提示 4 个 unused args**：启动时会打印
    `unused args [asr_capture_backend, asr_capture_source, asr_capture_volume,
    asr_capture_gain] for include of offline_voice_bridge/launch/offline_voice_zh.launch`。
    **这条不是警告，是致命错误**（roslaunch 直接退出）。原因是新版把 4 个
    PulseAudio 参数传给了本机这个还没升级的 `offline_voice_bridge` launch 文件，
    而 roslaunch 要求 include 时传的每个 `<arg>` 都必须在被包含文件里声明。
    已在 `offline_voice_zh.launch` 里补上声明并把参数接进了 ASR 节点。
16. **命令行传的参数可能被静默忽略**：roslaunch 不会因为传了未声明的参数而报错。
    `task1_owner_search_bringup.launch` 原本没声明 `use_jie_lidar_loc`，
    所以 `use_jie_lidar_loc:=false` 毫无作用、照样去启动不存在的 `jie_ware`。
    **以后传参没效果时，先回去确认那个 launch 到底有没有声明这个 arg。**
17. **`wpb_home_tutorials/maps/` 是个空目录**：它的 `.gitignore` 把目录下所有文件
    都忽略了，所以默认地图路径 `$(find wpb_home_tutorials)/maps/map.yaml` 不存在，
    `map_server` 启动即失败，进而 `map -> odom` 的 TF 建不起来、
    `move_base` 的代价地图一直超时。必须手动把地图复制进去。
18. **YOLO-World 缺 CLIP 会“假活”**：`yoloworld` 节点进程存在、`rosnode list`
    里能看到它，但内部卡在 `pip install git+https://github.com/ultralytics/CLIP.git`
    的自动重试上，`/perception/person_detections_2d` 永远没有数据。
    **判断方法**：看 `yoloworld-*-stdout.log`，正常应出现
    `YOLO-World warm-up complete`，日志里出现 `requirements:` / `AutoUpdate` 就是缺依赖。
19. **本机网络是受限的**：`pypi.org`、`pypi.tuna.tsinghua.edu.cn`（HTTPS）、
    `github.com` 都不通，但 **`codeload.github.com` 可以访问**。
    所以 `pip install` 基本用不了，要装 Python 包得走 codeload 下载源码再手动放置
    （见附录 B）。装任何东西之前先想清楚有没有离线替代方案。
20. **YOLO-World 首次加载要等约 110 秒**：它在下载并加载 CLIP 文本编码器权重。
    启动脚本里不要过早判断“YOLO 挂了”，看日志确认
    `Loading YOLO-World model` 之后是否出现了 `warm-up complete`。
21. **Clash 的“直连”节点会慢 15 倍**：全局模式下真正决定速度的是
    `GLOBAL` 组里选中的那个节点。`🇸🇬|新加坡-直连` 之类的“直连”节点等于从本机 IP
    出去，实测下载只有 **0.1 MB/s**；换成 `🇭🇰|香港家宽-中转 01` 后是 **1.48 MB/s**。
    **装任何大文件前先确认选的是“中转”或“IEPL”节点。**
    另外 Clash 的 `tun.enable` 是 `false`，所以**只有显式设了代理的程序才走代理**，
    命令行要自己加 `-x http://127.0.0.1:7897` 或 `export https_proxy=...`。
22. **`qwen3.5:0.8b` 不支持图片**（最坑的一个）：它的 manifest 只有
    `model/license/params` 三层、没有 vision projector，`model_family` 是 `qwen35`，
    `ollama show` 也只列出 `completion/tools`。而任务节点是要发图片做动作识别的。
    **判断一个 Ollama 模型能否看图，看 `ollama show` 的 Capabilities 里有没有 `vision`。**
    已换成 `qwen3-vl:2b-instruct`（family `qwen3vl`，实测有 `vision`）。
23. **`ollama pull` 走代理会报 EOF**：ollama 自带的下载器走 HTTP 代理访问
    `registry.ollama.ai` 时会 `EOF`，直连又只有 ~100KB/s（模型主体在 Cloudflare R2）。
    解决办法是用 curl 走代理下载分块、再手工写进 Ollama 的 blob 仓库，
    脚本见 `~/catkin_ws/competition/pull_ollama_model.py`（支持断点续传）。
24. **Ollama 用不了 CUDA，走的是 Vulkan**：驱动 535 对 Ollama 要求 550+，
    它会打印 `NVIDIA driver too old` 并自动退回 Vulkan 后端，**功能正常**，
    实测 `ollama ps` 显示 `100% GPU`。
25. **作者给的 `qwen_action_recognition_node.py` 是“纯姿态版”**：整份文件里
    没有任何 LLM 代码，缺 `PROMPT`（默认提示词）和 `merge_action_result`
    （5 参数版融合函数，任务节点实际调用的是它，文件里只有 3 参数的
    `merge_pose_action_result`）。已按调用契约本地补写（见附录 D）。
    **判断方法**：用任务节点自己的 `load_qwen_action_core()` 加载后检查这 5 个符号。
26. **torchreid 的依赖是“导入链式”的**，缺一个就 `ModuleNotFoundError`：
    按顺序会碰到 `gdown`（数据集模块）→ `tensorboard`（engine 模块）→
    `yacs`/`future`/`termcolor`。**不用跑 `pip install -e`**，
    因为脚本自己会把 `third_party/deep-person-reid` 加进 `sys.path`，
    补齐这几个依赖就够了。
27. **torchreid 默认下载的是 ImageNet 预训练权重，不是 ReID 权重**：
    `reid_model_path` 留空时它拉的是 `osnet_x0_25_imagenet.pth`。
    作者推荐的是 ReID 专用权重 `osnet_x0_25_msmt17.pth`，
    已下载并把两个 launch 的默认值指过去。
28. **`match_threshold: 0.70` 可能需要现场调**：用参考照片直接测时，
    同人不同角度的余弦相似度最小只有 0.43（ReID 权重），低于阈值。
    不过那几张是带背景的整图，实际运行时是 YOLO 裁出的人体框、干净得多，
    所以**必须在真机上用真实注册数据复测这个阈值**。

## 附录 C：安装 Ollama 与视觉模型

### 前提：先修好网络

Clash 是全局模式，但 `tun.enable: false`，**只有显式设置代理的程序才走代理**：

```bash
export https_proxy=http://127.0.0.1:7897
export http_proxy=http://127.0.0.1:7897
```

并且要在 Clash 里把 `GLOBAL` 组的节点换成**中转**类型（实测
`🇭🇰|香港家宽-中转 01` 可跑到 1.48 MB/s，而“直连”节点只有 0.1 MB/s）。
也可以直接在命令行查/切：

```bash
curl -s http://127.0.0.1:9097/proxies/GLOBAL | python3 -c \
  'import json,sys;print(json.load(sys.stdin)["now"])'
```

### 装 Ollama（免 sudo，装在用户目录）

官方二进制是 `.tar.zst` 格式，本机没有 `zstd`，用 Python 解压：

```bash
python3 -m pip install --user zstandard

U="https://github.com/ollama/ollama/releases/download/v0.34.4/ollama-linux-amd64.tar.zst"
curl -sSL -x http://127.0.0.1:7897 -o /tmp/ollama.tar.zst "$U"   # 约 1.4GB

python3 - <<'PY'
import zstandard, tarfile, os
with open('/tmp/ollama.tar.zst','rb') as f:
    with zstandard.ZstdDecompressor().stream_reader(f) as r:
        tarfile.open(fileobj=r, mode='r|').extractall(os.path.expanduser('~/.local'))
PY

~/.local/bin/ollama --version     # 应为 0.34.4
```

> 注意：`ollama.com/download/ollama-linux-amd64.tgz` 这个旧地址已经 404，
> 它会 307 跳到 GitHub Releases。

### 启动服务

```bash
bash ~/catkin_ws/competition/start_ollama.sh
```

### 装模型（关键：不能用 `ollama pull`）

`ollama pull` 走代理会 `EOF`，所以用手写脚本：

```bash
python3 ~/catkin_ws/competition/pull_ollama_model.py qwen3-vl 2b-instruct

```

## 附录 D：本地补写的两处接口（`qwen_action_recognition_node.py`）

### 为什么要补

作者提供的这份文件是**纯姿态版本**（整份文件没有任何 LLM 代码），而
`task1_find_owner_real.py` 在静态动作分支里要用到两个它没有的符号：

| 符号 | 任务节点在哪里用 | 文件里的情况 |
|---|---|---|
| `PROMPT` | 第 1428 行 `prompt or self.qwen_action_core.PROMPT` | 完全不存在 |
| `merge_action_result(qwen_action, place, pose_action, ground_relation, final_pose_is_horizontal)` | 第 2423 行 | 只有 3 参数的 `merge_pose_action_result` |

因为拿不到作者原版，我在文件里补写了这两处，位置都带明显的
`本地补写（本机适配）` 注释块，日后拿到原版可以整体替换。

### 怎么验证的

**① 按任务节点的真实加载路径检查符号**：调用任务节点自己的
`load_qwen_action_core("")`（与 `init_action_recognizer()` 同一条路径），
结果 5 个符号全部存在；`PoseActionAnalyzer` 用 `~/models/yolo11n-pose.pt`
初始化返回 `True pose model loaded`；`PointCloudGroundAnalyzer` 的 13 个参数
顺序与任务节点调用完全一致。

**② `merge_action_result` 决策表（8 个用例全部通过）**

| 场景 | 输入 | 输出 |
|---|---|---|
| 静态坐姿，点云无结论 | qwen=sitting, ground=unknown | `sitting / chair` |
| Qwen 说躺，点云确认在地面 | qwen=lying, ground_like | `fallen / floor` |
| Qwen 说躺，点云确认在家具 | qwen=lying, status=elevated | `lying / unknown` |
| 姿态判定突然摔倒 | pose=sudden_fall | `sudden_fall / floor` |
| 姿态判定挥手 | pose=waving | `waving / unknown` |
| Qwen 说挥手但姿态无证据 | qwen=waving, pose=unknown | `unknown / unknown` |
| 全部未知 | 都 unknown | `unknown / unknown` |
| Qwen 说摔但点云没确认 | qwen=fallen | `fallen / floor` |

判据优先级：姿态动态动作 > 点云地面判定 > 点云家具抬升 > Qwen 静态结论
> 姿态静态结论 > unknown。`fallen` 时强制 `place=floor`，与
`normalize_result()` 的既有语义一致。

**③ 端到端真实图片验证**：真实照片 -> `PROMPT` -> Ollama
(`qwen3-vl:2b-instruct`) -> 返回 JSON -> `parse_result` ->
`merge_action_result`，链路完整可用，CPU 下单次约 19-25s。
参考照片多为人像自拍（没有明确动作），模型返回 `unknown` 是**正确**判断。

### 需要你知道的局限

- `PROMPT` 的措辞是我按 `normalize_result()` 能识别的词表写的，
  **没有经过真实“坐 / 躺 / 摔倒”场景的准确率验证**。
- 必须用真人做三种动作实测一遍。如果识别不稳，优先调整 `PROMPT`
  里的判据描述，其次考虑换更大的视觉模型（如 `qwen2.5vl:3b`，约 3.0GB）。
- 真机联调时重点看这三行日志，确认它在正常工作：

```
Owner Qwen action recognition ready: model=qwen3-vl:2b-instruct core=...
Qwen owner static action parsed: action=... place=...
Owner action verdict: action=... place=... qwen=... used=... ground=... total=...s
```
