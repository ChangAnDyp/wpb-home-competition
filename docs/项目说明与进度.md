**为什么工具放在 `catkin_ws/competition/` 而不是 `catkin_ws/src/` 里？**
因为 `catkin_make` 只扫描 `src/`，放在根目录就不会被当成 ROS 包，也不影响编译。

**为什么不能把 `src/` 里的包搬到别处？** ROS 工作区路径写死在编译产物里
（`devel/` 下的脚本记录了绝对路径），搬动会导致所有包失效。

## 二、在 VS Code 里测试：详细步骤

### 0. 先理解一件事

ROS 节点**不能像普通 Python 脚本那样直接 F5**，因为它们必须：

1. 连上 ROS master（`roscore`）
2. 等相机、雷达等传感器就绪
3. 从参数服务器读取配置

所以流程永远是：**先启动机器人栈 → 再调试单个节点**。

### 1. 打开项目

双击桌面上的 **`启智机器人比赛.code-workspace`**。

（它指向 `~/catkin_ws/启智机器人比赛.code-workspace`。也可以
「文件 → 打开文件夹」直接选 `~/catkin_ws`。）

打开后侧边栏应看到 `src`、`competition`、`.vscode`，`build`/`devel` 已自动隐藏。

### 2. 启动机器人栈

三种方式**完全等价，任选一种就行**（不要两种同时用，否则两个栈会互相顶掉同名节点）。
栈只需要起一次；起来之后可以反复 F5 调试任务节点，不用每次重起栈。

**方式 A（推荐）**

1. 按 `Ctrl+Shift+D` 打开「运行和调试」面板
2. 顶部下拉框选 **`⑦【起栈】ROS: 启动机器人栈（含 TTS+ASR）`**
3. 按 **F5**

**方式 B**：`Ctrl+Shift+P` → `Tasks: Run Task` → 选 **`起栈：启动机器人栈（含 TTS+ASR）`**

> 注意：方式 B 是「任务」，只会出现在 **`Tasks: Run Task`** 这个列表里；
> 「运行和调试」面板的下拉框里只有调试配置（⑦ 起栈、① 节点等），看不到它。

**方式 C**：终端里直接跑

```bash
bash ~/catkin_ws/competition/robot.sh stack
```

（方式 C 不带语音识别，只适合不涉及语音的测试；要现场报名请用 A 或 B。）

**怎么知道栈起来了？** 看下方终端，等约 **1-2 分钟**，出现这行即就绪：

```
YOLO-World warm-up complete
```

想确认得更实在，另开终端跑：

```bash
rostopic hz /kinect2/qhd/image_color_rect      # 应约 30Hz
rostopic hz /perception/person_detections_2d   # 应约 14Hz
```

> 这一步会真的启动底盘、雷达、Kinect。机器人**不会移动**（要收到 `/cmd_vel` 才动）。
> 但后面扫描找人时它会**原地旋转**，周围留点空间。

### 3. 调试任务节点（核心步骤）

**步骤 1 · 打开要调试的文件**

左侧 `src/wpb_task1_owner_search/scripts/task1_find_owner_real.py`

**步骤 2 · 打断点**

在行号左侧点一下，出现**红点**。建议先打这几处：

| 位置 | 看什么 |
|---|---|
| 搜 `def enroll_owner` | 注册流程怎么走 |
| 搜 `def run_owner_task_at_waypoint` | 每个航点的任务逻辑 |
| 搜 `def recognize_owner_action` | 动作识别拿到了什么帧 |
| 搜 `def verify_candidate_with_face` | 人脸比对分数是多少 |
| 搜 `def merge_action_result` | 最终动作结论怎么融合出来的 |

**步骤 3 · 选调试配置**

「运行和调试」面板顶部下拉选 **`①【节点】调试任务节点 task1_find_owner_real（需先起栈）`**

**步骤 4 · 按 F5**

会发生：

1. 先自动执行前置任务「② 加载比赛参数到参数服务器」，终端出现 `比赛参数已加载`
2. 启动任务节点，程序在断点处停下
3. 顶部出现调试工具栏：继续 / 单步 / 重启 / **停止**

> 如果前置任务报连不上 master，说明**第 2 步的栈没起来**。

**⑤ 看代码怎么跑**

| 左侧面板 | 作用 |
|---|---|
| **调用堆栈** | 完整调用链，点哪层跳哪层 —— 这是"它调用了什么文件"最直观的答案 |
| **变量** | 当前作用域所有变量实时值，可展开嵌套结构 |
| **监视** | 手动填表达式持续观察，例如 `owner_candidate`、`len(frames)` |
| **断点** | 右键可设条件断点（例如只在 `score > 0.6` 时停） |

| 快捷键 | 作用 |
|---|---|
| `F5` | 继续到下一个断点 |
| `F10` | 单步跳过（不进函数） |
| `F11` | 单步进入（进函数内部，可进第三方库） |
| `Shift+F11` | 跳出当前函数 |
| `Ctrl+Shift+F5` | 重启调试 |
| `Shift+F5` | 停止调试 |

### 4. 调试结束后

**任务节点**：按调试工具栏的红色方块停止。

**机器人栈**：它**仍在后台运行**（方便你快速重跑任务节点）。
要全部停掉：`Ctrl+Shift+P` → `Tasks: Run Task` → **`③ 停止全部 ROS 进程`**

> **重要**：下次启动前**务必先停止**。残留进程会占着 Kinect 的 USB 接口，
> 导致下次启动直接报 `Initialization failed`。

### 5. 只想单独看动作识别？（更简单）

只验证"坐 / 躺 / 挥手 / 摔倒"判定时，不用跑整个任务节点。这部分已封装成一个
**独立 ROS 节点**，有两种用法，**推荐方式 B**——它和"融合进主任务"用的是同一个
节点、同一套参数。

#### 方式 A：VS Code 调试配置

1. 启动栈（第 2 步）
2. 调试面板选 **`② 调试动作识别 qwen_action_recognition_node`** → F5
3. 人站到相机前，在**弹出的窗口里按空格**触发一次识别
4. 终端打印结果；在 `analyze`、`merge_action_result` 处打点可看细节

#### 方式 B：launch 启动（推荐）

节点已封装为 `wpb_task1_owner_search/launch/qwen_action_recognition.launch`。
只用 YOLO-Pose 姿态 + 点云高度，**不调用 Qwen / Ollama**，姿态模型默认跑 GPU。

```bash
# 先确认机器人栈已启动（相机与点云由栈提供，本 launch 不重复启动）
bash ~/catkin_ws/competition/robot.sh stack

# 基础用法：启动时识别一次，之后按空格触发
roslaunch wpb_task1_owner_search qwen_action_recognition.launch

# 连续识别：每轮结束后隔 5 秒自动再来一次，结果画面保持 5 秒
roslaunch wpb_task1_owner_search qwen_action_recognition.launch \
  auto_repeat_seconds:=5.0 overlay_hold_seconds:=5.0

# 没有显示器时关掉预览窗口
roslaunch wpb_task1_owner_search qwen_action_recognition.launch show_window:=false

# 只看主人所在区域（ROI 为 x1,y1,x2,y2 像素坐标）
roslaunch wpb_task1_owner_search qwen_action_recognition.launch \
  use_owner_roi:=true owner_roi:="300,120,620,480"

# 查看结果（JSON：action / place / pose_confidence / 支撑面高度等）
rostopic echo /pose_action_recognition/result
```

常用参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `pose_device` | `cuda:0` | 姿态模型设备；CUDA 不可用会自动回退 CPU 并告警 |
| `pose_half` | `true` | GPU 上用 FP16 推理 |
| `pointcloud_camera_height` | `0.85` | 相机离地高度，决定"距地高度"换算是否准确 |
| `pointcloud_furniture_height_limit` | `0.40` | 家具面高度阈值，按赛事规则（方凳 0.4m）设定 |
| `auto_repeat_seconds` | `0.0` | 0 = 只识别一次；>0 = 每轮结束后隔这么久自动再识别 |
| `overlay_hold_seconds` | `5.0` | 结果画面（人体框 + 关键点 + 结论）保持秒数 |
| `result_topic` | `/pose_action_recognition/result` | 结果 JSON 的话题名 |
| `start_voice` | `false` | 置 true 时顺带拉起 TTS，让识别结果被念出来 |

**融合进主任务**时直接复用同一个文件（`owner_voice_reid_test.py` 就是这么调它的）：

```bash
roslaunch wpb_task1_owner_search qwen_action_recognition.launch \
  node_name:=owner_action_pose \
  result_topic:=/owner_voice_reid_test/action_result \
  show_window:=false auto_repeat_seconds:=0.0 use_owner_roi:=true
```

#### 圈2 与主任务内嵌识别的关系

两者**共用同一份算法代码**（`wpb_task1_owner_search/scripts/qwen_action_recognition_node.py`），
区别只在"谁来驱动"：

| 维度 | 圈2（独立节点 / 本 launch） | 主任务节点① |
|---|---|---|
| 代码关系 | 直接把这个文件当 ROS 节点整体运行 | 用 importlib 把它当模块导入，只取类与函数 |
| 执行者 | `PoseActionRecognitionNode` | `RealOwnerSearchBeforeAction` |
| 融合函数 | `merge_pose_action_result`（3 参数） | `merge_action_result`（5 参数） |
| 取景 | 全画面，或手动 `owner_roi` | 用 YOLO-World 行人检测**自动锁定主人**并裁剪 |
| 触发时机 | 启动 / 按空格 / 定时 | 走到航点、把主人居中之后调用 |
| 识别之后 | 只播报 | 走近主人 / 伸机械臂 / 语音交互 |
| 输出 | ROS 话题 + 播报 | 内部返回值，任务流程继续 |
| 运行形态 | 独立进程，可单独重启 | 与任务节点同进程 |

所以主任务**并没有另写一套 pose 识别代码**，它复用的就是同一个文件。

> 注意：**不要同时跑两个**。两边都会做姿态推理并抢 GPU，还会各自播报一次。
> 调试用圈2，正式跑用主任务节点①。

### 6. 完全不需要 ROS 的部分

比如 `feature_check.py`，直接选 **`⑥ 全功能体检`** → F5。

### 7. 常见问题速查

| 现象 | 原因与处理 |
|---|---|
| `owner_image_path is empty` | 比赛参数没加载。preLaunchTask 本应自动做；若被跳过，手动跑任务「② 加载比赛参数」 |
| 前置任务报 `Unable to communicate with master` | 机器人栈没启动，先做第 2 步 |
| `Initialization failed` / 相机无图像 | 有残留进程占着 Kinect → 先执行任务「③ 停止全部」，再重试 |
| 断点是灰色空心 | 程序不是调试模式启动的（要用 F5，不能直接终端跑） |
| 改了代码行为没变 | 确认已保存（`Ctrl+S`）；纯 Python 改动不需重新编译 |
| 提示 `RLException` / 找不到包 | 工作区没编译或没 source → 任务「⑤ 编译工作区」 |

## 七、常用命令速查

### 排错口诀

1. **先 `robot.sh stop`** —— 九成的"莫名其妙失败"都是残留进程占着设备
2. **看日志** —— `~/.ros/log/latest/` 按节点名分文件，直接搜 `CRITICAL` / `ERROR`
3. **动作识别失效** —— 确认有 `Owner action recognition ready: mode=YOLO-Pose only`；
   若走 GPU，还要看到 `Pose helper ready: ... device=cuda:0`，显示 `device=cpu`
   说明 CUDA 没生效（查 `python3 -c "import torch;print(torch.cuda.is_available())"`）
4. **人认不出来** —— 确认有 `face_ready=true`
5. **命令行传参没生效** —— roslaunch 对未声明参数**不报错、只忽略**
