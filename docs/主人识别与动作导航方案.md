# 主人识别、动作识别与导航当前方案及改进计划

更新时间：2026-10-25

适用范围：启智服务机器人主人寻找、身份确认、动作识别和走近交互

当前主测试入口：`.vscode/launch.json` 中的“⑯ 比赛整体流程”

## 1. 当前方案摘要

当前系统没有使用 Qwen 或大型视觉语言模型做动作判断。动作节点文件名虽然保留
`qwen_action_recognition_node.py`，实际使用的是 YOLO11n-Pose 关键点、时序规则和
Kinect 点云。主人身份由 InsightFace 人脸特征、OSNet 人体 ReID、姿态分流和
多人 margin 闸门共同决定。

整体链路：

1. YOLO11n-Pose 在彩色图中检测人体和人体关键点。
2. 用 OSNet 提取人体裁剪图的 ReID 特征。
3. 用 InsightFace 提取候选人体框中的人脸特征。
4. 分别与所有注册主人档案计算余弦相似度。
5. 计算主人身份分、当前帧 margin 和最近 5 帧的中位 margin。
6. 根据站姿、坐姿、躺姿分流应用不同的人脸、ReID 和绝对分数阈值。
7. 连续命中达到要求后确认主人。
8. 确认后触发 YOLO11n-Pose 动作识别。
9. 根据动作进入走近问答、摔倒协助或继续找下一位。

## 2. 当前模型和算法

### 2.1 人员检测

| 项目 | 当前配置 |
|---|---|
| 主检测器 | YOLO11n-Pose |
| 模型 | `/home/dyp/models/yolo11n-pose.pt` |
| 任务侧输入尺寸 | 640 |
| 任务侧设备 | CPU |
| 置信度 | 0.25 |
| NMS IoU | 0.45 |
| 每次最多候选 | 4，进入身份计算时最多保留前 3 个 |
| 最小人体框面积占比 | 1.5% |
| 兜底检测器 | YOLO-World `yolov8s-world-person.pt` |
| YOLO-World 输入尺寸 | 384 |
| YOLO-World 置信度 | 0.20 |
| YOLO-World 处理频率 | 每 3 帧一次 |

当前采用 `pose_first_detection=true`：YOLO11n-Pose 优先作为人体候选来源；
只有姿态模型没有得到候选时，才使用 YOLO-World 的结果。YOLO-World 本身仍会在
机器人栈中运行，但当前主人搜索的主检测路径是姿态模型。

### 2.2 人体 ReID

| 项目 | 当前配置 |
|---|---|
| 框架 | TorchReID |
| 模型 | OSNet x0.25 |
| 权重 | `osnet_x0_25_msmt17.pth` |
| 特征维度 | 512 |
| 设备 | ⑯使用 CUDA |
| 注册数据 | 正面 10 帧、侧面 6 帧 |
| 档案向量 | 16 个样本加 1 个平均向量，共 17 个 |
| 相似度 | 查询特征与档案库逐向量余弦相似度，取最大 |

人体 ReID 是非躺姿的主外观证据。正常情况下先对候选框做裁剪、缩放和归一化，
然后用 OSNet 提取 512 维单位向量。

### 2.3 人脸识别

| 项目 | 当前配置 |
|---|---|
| 框架 | InsightFace `FaceAnalysis` |
| 模型包 | `buffalo_sc` |
| 人脸检测模型 | `det_500m.onnx` |
| 人脸识别模型 | `w600k_mbf.onnx` |
| 输入尺寸 | 480 |
| 人脸检测阈值 | 0.35 |
| 设备 | ⑯使用 CUDA，CUDA 不可用时回落 CPU |
| 注册图片数 | 10 |
| 档案向量 | 10 个样本加 1 个平均向量，共 11 个 |

人脸相似度不是分类器的概率，而是两个归一化人脸特征的余弦相似度：

```text
face_score = max(cos(现场人脸特征, 注册人脸特征_i))
```

因此人脸分会受距离、脸部像素尺寸、侧脸角度、清晰度、遮挡和曝光影响。

### 2.4 身份分融合

人体 ReID、人脸、颜色直方图和姿态组成以下证据：

```text
人体外观分 body_score = OSNet 最大余弦相似度
人脸分 face_score = InsightFace 最大余弦相似度

普通姿态：
identity_score = 0.30 * body_score + 0.70 * face_score

躺姿：
identity_score = 0.90 * body_score + 0.10 * face_score
```

如果当前候选没有可用人脸，则不做人脸加权，身份分由 body_score 主导。

颜色直方图仍然存在并且会计算，但当前实际配置中：

- 普通姿态不使用颜色分；
- 躺姿颜色权重为 0；
- 躺姿最终主要由 OSNet ReID 决定。

## 3. margin 的含义和计算

margin 表示注册主人之间的身份分分离程度，不是人脸分，也不是“是主人的概率”。

计算过程：

1. 每个候选人体框对每位主人分别计算 `identity_score`。
2. 同一主人可能在多个候选框和裁剪变体中得到多个分数，当前取该主人在本帧的最高分。
3. 本帧 margin：

```text
frame_margin = 第一名主人身份分 - 第二名主人身份分
```

4. 对每位主人保存最近 5 帧身份分，并分别取中位数。
5. 最终 margin：

```text
owner_median_margin = 第一主人中位分 - 第二主人中位分
```

6. 当 `owner_median_margin < 0.04` 时，当前帧不确认最佳主人。

示例：

```text
李华 = 0.424
哪吒 = 0.446
乔治 = 0.368

margin = 0.446 - 0.424 = 0.022
```

这说明哪吒和李华在当前帧很难区分，不是哪吒的绝对相似度很高。

margin 只能回答“三位注册主人中谁更突出”，不能单独回答“是否真的是注册主人”。
绝对分数、人脸和 ReID 闸门仍然必须通过。高 margin 也可能发生在三人的绝对分都
很低时，因此必须同时检查绝对分。

## 4. 当前身份判定阈值

### 4.1 通用参数

| 参数 | 当前值 |
|---|---|
| 人脸接受阈值 | 0.45 |
| 人脸快速拒绝阈值 | 0.25 |
| 普通候选最低 ReID | 0.45 |
| 普通身份绝对分阈值 | 0.70 |
| margin 阈值 | 0.04 |
| margin 聚合窗口 | 最近 5 帧 |
| 连续命中次数 | 2 |
| 每帧候选框数 | 最多 3 |

### 4.2 站姿

- 有人脸时以人脸为准；
- 人脸分不低于 0.45 且 ReID 不低于 0.45 才接受；
- 完全没有人脸时，身份辅助通道要求人体分不低于 0.90；
- 姿态判成 `upright` 但常规通道被拒时，维持拒绝。

### 4.3 坐姿

- 有人脸但人脸分低于 0.45：直接拒绝；
- 完全没有人脸：进入坐姿外观通道；
- 坐姿外观通道要求身份分不低于 0.75、ReID 不低于 0.50；
- 小脸豁免参数 `sitting_ignore_small_face_px` 当前为 0，即关闭。

这是当前坐姿识别最容易受距离和脸部像素影响的一段逻辑。低质量小脸一旦被
InsightFace 检出，就会触发“检测到脸但不像主人”的直拒绝；完全检测不到脸反而
可以进入人体外观通道。

### 4.4 躺姿

- 躺姿绝对分阈值：0.60；
- 最低 ReID：0.50；
- 连续命中：2 次；
- 人体框宽高比不小于 1.25，或者框很短，或者躯干竖直度低于 0.45；
- 躺姿裁剪不使用额外 padding，并向内收 7%；
- 点云和姿态分别用于判断地面、床、沙发和椅子等支撑面。

## 5. 当前动作识别方案

### 5.1 输入

- 图像：`/kinect2/qhd/image_color_rect`
- 点云：`/kinect2/qhd/points`
- 一次识别约 5 秒，采集 9 帧；
- 动作姿态模型输入尺寸 640；
- 设备：⑯使用 CUDA；
- 主人 ROI：关闭，使用整帧并依靠主人框中心选择目标。

### 5.2 动作判据

| 动作 | 主要判据 |
|---|---|
| 挥手 | 手腕高于肩，至少 30% 帧；腕部运动幅度和路径超过阈值；存在换向 |
| 坐姿 | 最后 1/4 帧中 `sitting_like` 占比不低于 0.40；躯干竖直度高于 0.42，且屈膝或膝髋距离足够小 |
| 躺姿 | 最后 1/4 帧中 `lying_like` 占比不低于 0.40；躯干横置或人体框明显扁平 |
| 摔倒 | 从直立姿态快速转为低位，中心下降、躯干变化、宽高比变化等多项同时成立 |
| unknown | 关键点不足、遮挡严重、阈值为通过或点云与二维证据冲突 |

### 5.3 点云支撑面

- 相机离地高度自动标定；
- 地面高度阈值：0.35 m；
- 家具面高度阈值：0.40 m；
- 根据支撑面区分地面上的 `fallen` 和家具上的 `lying`；
- 点云只用于支撑面和 3D 腿部几何，不替代 YOLO-Pose。

### 5.4 3D 坐姿兜底

只有二维姿态判成 `unknown` 时才尝试：

- 大腿与竖直方向夹角不高于 62°；
- 髋膝落差不超过 0.30 m；
- 大腿水平投影不少于 0.15 m；
- 躯干竖直度不低于 0.80；
- 默认不限制二维膝髋比。

### 6.3 走近主人

挥手和摔倒均使用方案 B-2：

1. 从人体框和点云快照估计主人的三维位置；

6. 默认禁止纯里程计盲走；

## 8. 为什么相同航点和相同坐姿可能一次成功、一次失败

“机器人到同一个航点”只能保证机器人起点大致相同，不能保证以下条件相同：

1. 人的实际位置和朝向；
2. 人脸到相机的距离和脸部像素尺寸；
3. 坐姿高度、腿部遮挡和相机俯角；
4. 衣服颜色、光照、曝光和反光；
5. 画面中其他人和椅子的位置；
6. 当次注册档案的质量；
7. 注册主人数量。

2026-10-17 的两轮日志可以说明这一点：

- 14:24 的自测使用 2 位主人档案，乔治在同一轮中曾出现人体分 0.854、脸部相似度
  0.430 的候选，该帧被拒绝，但后续帧最终成功确认；
- 17:06 的志愿者测试使用 3 位主人档案，坐姿帧的脸部短边只有 7～31 像素，
  脸部相似度约 0.03～0.34；
- 同一轮中，志愿者的人体分曾达到 0.775～0.789，已经达到坐姿人体阈值 0.75，
  但因为检测到了一张低质量小脸，被坐姿分支的“脸不像主人”规则直接否决；
- 17:06 的 19 次 margin 汇总中，有 9 次小于 0.04；
- 当前三份档案的人体跨主人最大余弦约为 0.649～0.704，而坐姿人体阈值是 0.75，
  两者余量并不大；
- 当前三份档案的人脸跨主人最大余弦约为 0.242～0.355，低于 0.45，
  说明清晰人脸的区分度尚可，问题主要是现场小脸质量不足和身份融合不稳定。
- 三份志愿者的注册人脸库内部中位相似度约为 0.879～0.961，样本较集中；
  这提高了稳定性，但也说明 10 张人脸可能主要来自相同角度，未覆盖远距离、
  侧脸和坐姿场景。

因此，同一姿势结果不同不是单一“坐姿模型随机”，而是下面几个边界条件共同作用：

- 人脸是硬否决，小脸误检的伤害可能大于完全检测不到脸；
- 人体 ReID 在站立注册、远距离坐姿查询之间存在域差；
- 2 位主人和 3 位主人的 margin 难度不同；
- 志愿者和自测者在画面中的真实距离、角度和服装不同；
- 当前要求连续命中 2 次，旋转时某一帧失败会打断连续计数；
- margin 和历史身份分没有按人体 track 分离，多人同框时可能混合不同候选框的证据。

## 9. 改进方案

### P0：按人体 track 计算身份和 margin

当前问题：

- 每份主人的最高分可能来自不同候选框；
- 最近 5 帧历史没有按具体人 track 隔离；
- 旋转扫描时人脸有无切换会改变身份分的尺度。

改进：

1. 用人体框 IoU、中心距离和关键点相似度建立轻量 track；
2. 每个 track 分别计算对三位主人的分数和候选 margin；
3. 每个 track 独立做最近 5 帧聚合；
4. 只对同一个 track 应用连续或 N-of-M 命中；
5. 不再把一个画面中不同人的最高分合并后计算 margin。

原因：

这是当前多人同框、三人档案 margin 不稳的结构性原因。该改动不需要更换模型，
预期比继续微调 0.04 阈值更有效。

验收：

- 同一批 3 人坐姿测试中，主人身份正确率提高；
- 不同候选框导致的 margin 抖动减少；
- 不增加陌生人误确认。

### P0：人脸改为质量感知闸门

当前问题：

- 小脸只要被检测到就会参与坐姿硬否决；
- 7～31 像素的人脸相似度接近噪声；
- 当前小脸豁免关闭。

改进：

1. 记录人脸短边、检测置信度、侧脸角和清晰度；
2. 小脸或严重侧脸不参与“不是主人”的硬否决；
3. 低质量脸只作为弱证据；
4. 进入人体外观通道时仍要求高阈值 ReID 和足够 margin；
5. 先以 35～40 像素作为可测试起点，最终值通过正负样本校准。

原因：

坐姿失败不是没检测到主人，而是低质量脸把本来可通过的高 ReID 候选否决。
质量感知分流可以在不全局降低 0.45 阈值的情况下减少漏认。

验收：

- 坐姿主人漏认率下降；
- 陌生人接受率不上升；
- 人脸像素、相似度和最终决策出现在同一条日志中。

### P1：注册档案从最大值改为稳健聚合

当前问题：

- 人体 17 个向量和人脸 11 个向量都取最大余弦；
- 单个偶然相似样本可以抬高分数；
- 档案中可能有近重复图片。
- 固定 0.45 人脸阈值对不同人是“同一条线”，但每位主人的类内相似度并不相同。

改进：

1. 对候选与档案库的相似度使用 Top-3 平均或中心加近邻；
2. 保留最大相似度作为诊断，不直接把最大值当最终分；
3. 注册时按质量、角度和重复度选样；
4. 保持 10 张人脸名额，不增加采集时间，只提高样本多样性。
5. 注册完成后做 leave-one-out 自检：每张注册脸依次与其余注册脸比较；
6. 记录每位主人自己的真身份分分布，质量过低的档案应重新注册，而不是降低全局阈值；
7. 在样本量足够后，可对每人使用相对其档案分布归一化的接受线。

原因：

最大值容易对少量注册帧过拟合，并抬高不同主人之间的交叉分。稳健聚合能改善
margin 的可重复性。固定阈值还会让天生类内相似度较低的志愿者更容易漏认，
按档案质量检查和归一化可以降低这种个体差异。

### P1：融合姿态检测和 YOLO-World，而不是互斥兜底

当前问题：

- 姿态模型一旦返回任意候选，YOLO-World 结果就不参与；
- 单个姿态误检可能遮住 YOLO-World 的有效人体框。

改进：

1. 合并姿态和 YOLO-World 的人体框；
2. 做类别统一和 NMS/IoU 去重；
3. 两个模型都支持同一框时提高置信度；
4. 保留姿态关键点用于后续坐姿、躺姿和 3D 判断。

原因：

两个模型对站立、坐姿、侧躺和遮挡的检出能力不同，融合比二选一更稳定。

### P1：统一配置源

当前风险：

- 旧 `owner_voice_reid_test.launch` 仍写着躺姿连续 3 次、裁剪 padding 0.22、
  ReID/颜色权重 0.75/0.25；
- 当前代码默认值已经是连续 2 次、padding 0、ReID/颜色权重 1.0/0；
- ⑯直接运行 Python 时使用代码值，旧 launch 启动时行为不同。

改进：

- 建立一份统一 YAML 作为唯一参数源；
- launch 和 VSCode 都只引用该配置；
- 删除已废弃参数；
- 启动时打印完整身份判定配置摘要。

原因：

避免现场误以为修改已经生效，实际却被旧 launch 默认值覆盖。

### P2：动作识别增加关键点时序模型

当前规则已经可解释，但连续坐姿仍受关键点抖动和遮挡影响。

建议：

1. 保留 YOLO11n-Pose 作为关键点提取器；
2. 将每帧 17 个关键点组成 5～9 帧序列；
3. 训练轻量 ST-GCN、1D-CNN 或小型 Transformer；
4. 与现有规则做加权融合；
5. 3D 坐姿阈值按躯干长度和腿长归一化。

原因：

轻量时序模型可以学习动作变化，不需要引入大型视觉语言模型，适合当前 4 GB 显存。

### P2：导航取消和恢复逻辑

改进：

1. 导航超时后等待 move_base 真正进入取消或中止状态，再发起下一动作；
2. 窄处失败后先退出，不在障碍旁反复旋转；
3. 狭窄房间增加中间航点；
4. 用 rosbag 记录 `/amcl_pose`、`/odom`、`/cmd_vel`、`/tf` 和 `/scan`；
5. 区分定位漂移、局部规划振荡和目标点安全距离不足。

原因：

现有失败日志中已经出现目标超时后 move_base 仍在恢复状态，以及窄处旋转恢复
判定会碰撞的问题。

## 10. 推荐实施顺序

1. 只增加诊断：人脸短边、置信度、侧脸角、清晰度、人体 track ID 和每个 track
   的三位主人分数。
2. 实现按 track 的 margin 和 N-of-M 命中，不改绝对阈值。
3. 打开低质量小脸分流，在人脸小于约 40 像素时改走严格人体外观通道。
4. 比较 Top-3 均值与当前最大值，确定档案库聚合方式。
5. 用 3 位主人、坐姿、2～3 米距离、正脸和侧脸各采集正负样本，校准阈值。
6. 最后再评估轻量动作时序模型和导航恢复逻辑。

## 12. 当前结论

当前方案的主要问题不在“没有坐姿模型”或“InsightFace 模型完全无效”。

更准确的结论是：

- 坐姿检测本身已经能多次成功；
- 小脸、多人同框、注册档案域差和 margin 身份关联会造成边界结果随机；
- 当前坐姿分支对“低质量但检测到了脸”的处理过于硬；
- 当前 margin 没有按具体人体 track 隔离；
- 人体 ReID 跨主人最大分与坐姿阈值距离较近；
- 同一航点并不能控制人与相机的真实距离和角度，因此不能保证同一可识别条件。

最优先的改法是按人跟踪身份证据，并对低质量人脸做质量感知分流，而不是继续
大幅降低全局人脸阈值或修改坐姿动作本体。
